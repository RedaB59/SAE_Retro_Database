\section{Introduction et architecture générale}
% ══════════════════════════════════════════════════════════════════════════════

\subsection{Contexte et objectif}

Ce projet porte sur la construction d'un \textbf{pipeline de données complet}
pour analyser les mutations immobilières françaises à partir des données
publiques \textbf{DVF} (\textit{Demandes de Valeurs Foncières}), publiées
par la DGFiP. L'objectif est de transformer un fichier CSV brut en un
\textbf{entrepôt analytique} avec historisation SCD2 intégrale.

\section{Source de données DVF}
% ══════════════════════════════════════════════════════════════════════════════

\subsection{Format du fichier CSV}

Les données DVF sont publiées en open data sur \texttt{data.gouv.fr}.
Le fichier CSV est \textbf{dénormalisé} : une ligne contient simultanément
les informations de mutation, parcelle, local, lots et adresse.

\begin{table}[H]
  \centering
  \rowcolors{2}{gray!10}{white}
  \begin{tabularx}{\linewidth}{llX}
    \toprule
    \textbf{Groupe} & \textbf{Colonnes principales} & \textbf{Description} \\
    \midrule
    Transaction  & \texttt{id\_mutation}, \texttt{date\_mutation},
                   \texttt{valeur\_fonciere}, \texttt{nature\_mutation}
                 & Identifiant, date notariée, prix €, type \\
    Parcelle     & \texttt{id\_parcelle}, \texttt{code\_nature\_culture},
                   \texttt{surface\_terrain}
                 & Référence cadastrale, nature sol, surface m² \\
    Bâtiment     & \texttt{code\_type\_local}, \texttt{surface\_reelle\_bati},
                   \texttt{nombre\_pieces\_principales}, \texttt{nombre\_lots}
                 & Type bâtiment, surface, pièces, lots \\
    Lots         & \texttt{lot1\_numero} \ldots \texttt{lot5\_numero},
                   \texttt{lot1\_surface\_carrez} \ldots \texttt{lot5\_surface\_carrez}
                 & Jusqu'à 5 lots en colonnes larges (\textit{wide format}) \\
    Adresse      & \texttt{adresse\_code\_voie}, \texttt{adresse\_nom\_voie},
                   \texttt{latitude}, \texttt{longitude}
                 & Code FANTOIR, coordonnées WGS84 \\
    Commune      & \texttt{code\_commune}, \texttt{nom\_commune},
                   \texttt{code\_departement}, \texttt{code\_postal}
                 & Référentiels géographiques INSEE \\
    \bottomrule
  \end{tabularx}
  \caption{Groupes de colonnes du fichier CSV DVF}
\end{table}

\begin{warnbox}[Problèmes du format dénormalisé]
\begin{itemize}[noitemsep]
  \item \textbf{Redondance} : commune et département répétés pour chaque ligne d'une même mutation.
  \item \textbf{Lots en colonnes larges} : 5 lots encodés en \texttt{lot1\_*} à \texttt{lot5\_*} au lieu d'une relation one-to-many.
  \item \textbf{Clés manquantes} : \texttt{id\_adresse} et \texttt{id\_local} n'existent pas dans le CSV -- à générer.
\end{itemize}
\end{warnbox}

\subsection{Lecture du CSV et nettoyage}

\begin{lstlisting}[language=Python, caption={Lecture du fichier CSV DVF}]
df = pd.read_csv("dvf.csv", dtype=str, sep=",")
df = df.where(pd.notnull(df), None)  # NaN -> None (NULL SQL)
\end{lstlisting}

\begin{infobox}[\texttt{dtype=str} : pourquoi ?]
Lire tout comme chaîne évite l'inférence incorrecte de types (ex.\ code postal
\texttt{"01000"} converti en entier \texttt{1000}). Les casts sont délégués à
la couche Staging dbt.
\end{infobox}

\subsection{Normalisation en 13 tables}

\begin{lstlisting}[language=Python, caption={Exemples de normalisation}]
# Departements : dedoublonnage simple
df_departements = df[["code_departement"]].drop_duplicates().dropna()

# nature_mutation : generation d'un id sequentiel
df_nm = df[["nature_mutation"]].drop_duplicates().dropna().reset_index(drop=True)
df_nm["id_nat_mut"] = df_nm.index + 1
nat_mut_map = dict(zip(df_nm["nature_mutation"], df_nm["id_nat_mut"]))

# id_adresse : cle generee par concatenation (reproductible)
df_loc_raw["id_adresse"] = (
    df_loc_raw["code_commune"] + "_" +
    df_loc_raw["adresse_code_voie"] + "_" +
    df_loc_raw["adresse_numero"].fillna("0")
)

# Lots : pivot wide -> tall (lot1_* a lot5_* -> une ligne par lot)
lots_frames = []
for i in range(1, 6):
    tmp = df[["id_mutation","id_parcelle",
              f"lot{i}_numero", f"lot{i}_surface_carrez"]].dropna(subset=[f"lot{i}_numero"])
    tmp = tmp.rename(columns={f"lot{i}_numero": "id_lot",
                               f"lot{i}_surface_carrez": "lot_surface_carrez"})
    lots_frames.append(tmp[["id_lot","id_local","lot_surface_carrez"]])
df_lots = pd.concat(lots_frames).drop_duplicates(subset=["id_lot"])
\end{lstlisting}

\subsection{Insertion en base PostgreSQL}

\begin{lstlisting}[language=Python, caption={Insertion batch avec ON CONFLICT DO NOTHING}]
def inserer(cursor, table, df, colonnes):
    donnees = [tuple(r) for r in df[colonnes].itertuples(index=False)]
    execute_values(cursor,
        f"INSERT INTO {table} ({', '.join(colonnes)}) VALUES %s ON CONFLICT DO NOTHING",
        donnees)
    return len(donnees)

# Ordre respectant les cles etrangeres
etapes = [
    ("departements", df_dep, ["code_dep","lib_dep"]),
    ("communes",     df_com, ["code_com","code_postal","lib_com","code_dep"]),
    ("nature_mutation", df_nm, ["id_nat_mut","lib_nat_mut"]),
    # ... 10 autres tables dans l'ordre FK
    ("parcelles_mutations", df_pm, ["id_mutation","id_parcelle"]),
]
conn.autocommit = False
for table, df_t, cols in etapes:
    n = inserer(cur, table, df_t, cols)
    print(f"  {table:<28} -> {n} lignes")
conn.commit()
\end{lstlisting}

\begin{successbox}[Transaction globale + idempotence]
Les 13 insertions sont dans une seule transaction (\texttt{autocommit = False}).
\texttt{ON CONFLICT DO NOTHING} rend le script idempotent : rejouable sans erreur.
\texttt{execute\_values} est ~100x plus rapide qu'un INSERT par ligne.
\end{successbox}

\subsection{Staging -- typage et renommage (vues)}

Chaque modèle staging effectue uniquement : cast de types, renommage et
horodatage \sql{\_loaded\_at}. Matérialisé en \textbf{vue} pour éviter la
duplication de données.

\begin{lstlisting}[language=SQL, caption={stg\_mutations.sql}]
select id_mutation,
       numero_mutation::int       as numero_mutation,
       date_mutation::date        as date_mutation,
       valeur_fonciere::bigint    as valeur_fonciere,
       id_nature_mutation::int    as id_nature_mutation,
       date_chargement,
       current_timestamp          as _loaded_at
from {{ source('DSA', 'mutations') }}
\end{lstlisting}

\subsection{Intermédiaire -- logique métier (tables)}

\begin{lstlisting}[language=SQL, caption={int\_transactions.sql -- déduplication append-only}]
with mutations_brutes as (
    select m.*, pm.id_parcelle,
           row_number() over (
               partition by m.id_mutation
               order by m.date_chargement desc  -- derniere version
           ) as rn
    from {{ ref('stg_mutations') }} m
    join {{ ref('stg_parcelles_mutations') }} pm on pm.id_mutation = m.id_mutation
),
mutations_latest as (select * from mutations_brutes where rn = 1)

select id_mutation, date_mutation, valeur_fonciere,
       count(distinct id_parcelle) as nb_parcelle,
       md5(concat_ws('|', id_mutation, date_mutation::text,
                     valeur_fonciere::text)) as hash_contenu
from mutations_latest
group by id_mutation, date_mutation, id_nature_mutation, valeur_fonciere
\end{lstlisting}

\begin{infobox}[Pattern append-only + déduplication]
La source \texttt{DSA.mutations} accumule les versions sans mise à jour.
\texttt{ROW\_NUMBER() PARTITION BY id\_mutation ORDER BY date\_chargement DESC}
isole la version la plus récente avant agrégation.
\end{infobox}

\section{Couche ODS -- Historisation SCD2}
% ══════════════════════════════════════════════════════════════════════════════

\subsection{Principe du SCD Type 2}

\begin{table}[H]
  \centering
  \rowcolors{2}{gray!10}{white}
  \begin{tabularx}{\linewidth}{lX}
    \toprule
    \textbf{Colonne} & \textbf{Signification} \\
    \midrule
    \sql{ods\_sk}       & \sql{md5(id || '|' || hash\_contenu)} -- clé de substitution par version \\
    \sql{hash\_contenu} & MD5 des colonnes métier -- détecte les changements \\
    \sql{date\_debut}   & Horodatage d'entrée en vigueur \\
    \sql{date\_fin}     & \sql{'9999-12-31'} si courant, sinon date de fermeture \\
    \sql{est\_courant}  & \sql{true} = version active \\
    \sql{statut\_*}     & \sql{'VALIDE'} ou \sql{'EXPIRE'} \\
    \bottomrule
  \end{tabularx}
  \caption{Colonnes SCD2 dans les tables ODS}
\end{table}

\begin{figure}[H]
  \centering
  \includegraphics[width=\linewidth]{ODS.png}
  \caption{Couche ODS (schéma \texttt{Intermediate}) -- tables et relations SCD2}

\subsection{Macro \texttt{scd2\_close\_records} et modèle \texttt{ods\_transaction}}

\begin{lstlisting}[language=Jinja, caption={Macro de fermeture SCD2 (post\_hook)}]
{% macro scd2_close_records(target_table, id_col, hash_col, statut_col) %}
UPDATE {{ target_table }} AS cible
SET date_fin = current_timestamp, est_courant = false, {{ statut_col }} = 'EXPIRE'
WHERE cible.est_courant = true
AND EXISTS (
    SELECT 1 FROM {{ target_table }} n
    WHERE n.{{ id_col }} = cible.{{ id_col }}
      AND n.{{ hash_col }} != cible.{{ hash_col }}
      AND n.est_courant = true AND n.date_debut > cible.date_debut
);
{% endmacro %}
\end{lstlisting}

\begin{lstlisting}[language=Jinja, caption={ods\_transaction.sql -- modèle incrémental SCD2}]
{{ config(materialized='incremental', unique_key='ods_sk',
  post_hook=["{{ scd2_close_records(this,'id_mutation','hash_contenu',
                                    'statut_transaction') }}",
             "CREATE INDEX IF NOT EXISTS idx_ods_trx_courant ON {{ this }}(est_courant)",
             "ANALYZE {{ this }}"]) }}

select md5(concat_ws('|', s.id_mutation, s.hash_contenu)) as ods_sk,
       gen_random_uuid()        as id_transaction,
       s.id_mutation, s.valeur_fonciere, s.nb_parcelle, s.hash_contenu,
       current_timestamp        as date_debut,
       '9999-12-31'::timestamp  as date_fin,
       true                     as est_courant,
       'VALIDE'                 as statut_transaction
from {{ ref('int_transactions') }} s
{% if is_incremental() %}
where not exists (
    select 1 from {{ this }} t
    where t.hash_contenu = s.hash_contenu and t.est_courant = true
)
{% endif %}
\end{lstlisting}

\begin{successbox}[Fonctionnement en deux temps]
\textbf{1. INSERT} -- nouvelle version insérée avec \sql{est\_courant=true} et \sql{date\_fin='9999-12-31'}.\\
\textbf{2. UPDATE} (post\_hook) -- \texttt{scd2\_close\_records} ferme l'ancienne version
dès que deux versions avec des hash différents coexistent.
\end{successbox}

\subsection{Modèles du DWH}

\textbf{\texttt{dim\_temps}} génère toutes les dates via \sql{generate\_series}
avec année, mois, trimestre et libellés. Matérialisé en table statique.

\textbf{\texttt{type\_mutation}} et \textbf{\texttt{localisation}} propagent
les colonnes SCD2 depuis l'ODS, permettant d'interroger l'état d'une
dimension à n'importe quelle date (\sql{WHERE est\_courant=true} = état actuel).

\begin{lstlisting}[language=Jinja, caption={fact\_mutation.sql -- post\_hook de synchronisation SCD2}]
{{ config(materialized='incremental', unique_key='sk_mutation',
  post_hook=["""
    UPDATE {{ this }} fm
    SET est_courant = ot.est_courant, date_fin = ot.date_fin
    FROM {{ ref('ods_transaction') }} ot
    WHERE fm.id_mutation = ot.id_mutation
      AND fm.sk_mutation = ot.ods_sk
      AND fm.est_courant != ot.est_courant
  """]) }}

select t.ods_sk            as sk_mutation,
       t.id_mutation,
       t.id_nature_mutation::varchar as id_type_mutation,
       t.date_mutation      as id_date,
       t.valeur_fonciere,
       avg(b.surface_batiment)   as avg_surface_bat,
       avg(b.surface_terrain)    as avg_surface_terrain,
       t.nb_parcelle, t.date_debut, t.date_fin, t.est_courant
from {{ ref('ods_transaction') }} t
left join {{ ref('ods_bien_immobilier') }} b on b.id_parcelle=t.id_parcelle
join {{ ref('dim_temps') }} dt on dt.date_=t.date_mutation
join {{ ref('type_mutation') }} tm on tm.id_type_mutation=t.id_nature_mutation::varchar
{% if is_incremental() %}
where not exists (select 1 from {{ this }} fm where fm.sk_mutation=t.ods_sk)
{% endif %}
group by t.ods_sk, t.id_mutation, t.id_nature_mutation,
         t.date_mutation, t.valeur_fonciere, t.nb_parcelle,
         t.date_debut, t.date_fin, t.est_courant
\end{lstlisting}

\begin{table}[H]

\section{Conclusion}
% ══════════════════════════════════════════════════════════════════════════════

Ce projet implémente un pipeline industriel complet en quatre grandes étapes :

\begin{enumerate}[noitemsep]
  \item \textbf{Injection Python} -- normalisation du CSV dénormalisé en 13 tables,
        génération des clés manquantes, insertion idempotente en lot.
  \item \textbf{Pipeline dbt 4 couches} -- Staging (typage), Intermédiaire (logique
        métier + hash), ODS (SCD2 incrémental), DWH Marts (étoile analytique).
  \item \textbf{SCD2 généralisé} -- 8 tables ODS + table de faits historisée via
        macro \texttt{scd2\_close\_records} et post\_hook de synchronisation.
  \item \textbf{Dashboard interactif} -- 7 onglets, carte choroplèthe, filtre
        commune dynamique, prix/m², toutes les requêtes agrégées côté PostgreSQL.
\end{enumerate}

\textbf{Perspectives :} orchestrateur (Airflow/Dagster) pour automatisation,
enrichissement INSEE (revenus/démographie), géolocalisation PostGIS.
